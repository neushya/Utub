## ⚠️ 0. 아키텍처 전환 (2026-08-17, 통합테스트 중 결정)

통합테스트 중 사용자 피드백("화면이 유튜브와 다르다")에 따라 **탐색 UI를 자체 네이티브 → WebView 하이브리드로 전환**했다. (배경·근거는 memory [[utub-hybrid-pivot]], 상세 설계는 docs/04 갱신분)

- **탐색/검색/상세/연관영상/댓글/채널**: 유튜브 모바일 웹(m.youtube.com)을 WebView로 그대로 노출 → 유튜브와 동일한 화면
- **일반 영상(watch)**: 클릭을 가로채 우리 네이티브 Media3 플레이어로 재생 → 광고 없음·백그라운드·화면 꺼짐 재생 유지
- **상세화면**: 방식 A(겹치기) — 상단 16:9에 네이티브 플레이어 오버레이 + 하단은 웹뷰(영상정보·댓글·연관영상). 연관영상 탭 시 오버레이 플레이어가 새 영상으로 교체
- **쇼츠(shorts)**: 가로채지 않고 웹에 위임 (세로 스와이프 재미 유지, 그때만 광고·백그라운드 없음) — 기존 "Shorts 전용 UI 범위 제외" 합의와 일치
- **로컬 보관함**(시청기록·즐겨찾기 등): 유튜브 웹 화면 안엔 못 섞이므로 우리 앱 **별도 탭**으로 유지
- **광고**: 영상 재생 광고는 0(우리 플레이어). 단, 웹 탐색 화면의 목록/배너 광고는 CSS/JS로 "최선 노력" 차단(유튜브 웹 변경 시 깨질 수 있음 — 완전 차단 보장 안 함)

아래 1~6장의 자체 네이티브 탐색 화면(SCR-010/100/200/600 등)은 위 전환으로 **웹뷰가 대체**한다. 재생·서비스·보관함·설정 관련 화면(SCR-300 오버레이화/310/320/500/700/800)은 그대로 유지·재사용한다.

## 1. 정보 구조 (IA / 네비게이션)

```
┌─────────────────────────────┐
│ 상단바: 로고 · 검색 🔍 · 설정 ⚙ │
├─────────────────────────────┤
│                             │
│        (탭 콘텐츠 영역)        │
│                             │
├─────────────────────────────┤
│ 미니플레이어 (재생 중 상시 표시)  │ ← 위로 스와이프 → 전체 플레이어
├─────────────────────────────┤
│   홈    |   구독   |  보관함    │ ← 하단 3탭 (유튜브 앱과 동일 구성)
└─────────────────────────────┘
```

- **하단 3탭**: 홈(피드) / 구독(로컬 구독 피드) / 보관함(기록·재생목록·다운로드)
- **미니플레이어**: 재생 중 하단 탭 위에 상시 고정. 탭하거나 위로 스와이프 시 전체 플레이어 확장
- **시스템 레벨**: MediaSession 기반 알림바·잠금화면 컨트롤러, 블루투스 제어
- **1차 MVP의 홈**: 정식 피드 대신 **간이 홈** — 검색창 + 링크 붙여넣기 + 최근 재생 목록. 2차에서 정식 홈 피드로 교체

## 3. 주요 사용자 흐름

1. **공유하기로 즉시 재생 (핵심)**: 유튜브 앱에서 공유 → UTub 선택 → 스트림 추출 → 플레이어 자동 진입, 광고 없이 재생 → 홈 버튼/화면 꺼도 재생 유지
2. **앱 내 검색 재생**: 검색 → 결과 탭(즉시 재생) 또는 더보기로 "다음에 재생/대기열 추가" → 연속 재생
3. **화면 끄고 잠금화면 제어**: 재생 중 전원 버튼 → 비디오 렌더링만 해제(오디오 유지) → 잠금화면/알림에서 재생·이전·다음·종료, 블루투스 버튼 제어 → 화면 켜면 영상 복원
4. **재생 종료 (화면 꺼짐/백그라운드 상태에서)**: 알림 X 버튼 → 즉시 종료. 그 외 아래 종료 정책 표 참조
5. **Takeout 가져오기 (2차)**: 설정/보관함 → 파일 선택 → 배치 등록 → 구독 탭 자동 반영

## 4. 핵심 UX 정책

### 4.1 백그라운드 재생 설정 (사용자 요청 반영)
- 설정 > 재생 > **백그라운드 재생 모드**:
  - **항상 켬 (기본값)** — 화면 꺼짐/앱 이탈 시에도 계속 재생
  - **이어폰/외부기기 연결 시에만**
  - **끔** — 화면 꺼짐/앱 이탈 시 일시정지 (일반 유튜브 앱과 동일)

### 4.2 재생 종료 정책 (사용자 요청 반영)

| 트리거 | 동작 |
|---|---|
| 알림/잠금화면 X 버튼 | 즉시 재생 종료 + 서비스·알림 제거 |
| 알림 스와이프 | 재생 중엔 고정(불가), 일시정지 상태에선 스와이프 시 완전 종료 |
| 최근 앱에서 앱 스와이프 | 재생 중이면 재생 유지(음악 앱 관례), 일시정지 상태면 완전 종료 |
| 미니플레이어 X / 좌·우 스와이프 | 재생 종료 (아래 방향은 OS 내비게이션 제스처와 충돌하므로 좌·우 방식 채택 — agy 검토 반영) |
| 대기열 끝 + 자동재생 꺼짐 | 재생 완료 → 유예 후 서비스 자동 정리(배터리 보호) |
| 이어폰/블루투스 분리 | 자동 일시정지 (소리 유출 방지) |
| 취침 타이머 만료 | 페이드아웃 후 종료. 타이머: 15/30/60분/현재 영상 끝까지 |

### 4.3 오디오/비디오 모드
- 플레이어 토글로 **오디오 전용 모드** 전환: 오디오 스트림만 수신(데이터·배터리 절감), 앨범아트 표시
- 비디오 모드 중 화면 꺼짐 → 비디오 디코딩만 해제, 오디오 연속. 화면 켜면 싱크 유지한 채 영상 복원

### 4.4 대기열·연속 재생
- 검색/피드에서 탭 → 즉시 재생. 더보기 → "다음에 재생" / "대기열에 추가"
- **연관 영상 자동 연속재생**: 대기열이 비면 연관 영상 자동 재생 (설정에서 켬/끔, 기본 켬 — 유튜브 앱과 동일 사용감)
- 대기열·재생 지점은 로컬 DB에 보존, 앱 재시작 시 복원 (2차)

### 4.5 이어보기 (2차)
- 1분 미만 영상 제외. 95% 이상 시청 시 '완료' 처리(다음엔 처음부터). 그 외 마지막 지점부터 재생

### 4.6 권한 온보딩
- 첫 실행 1회: ① 알림 권한(POST_NOTIFICATIONS) ② 배터리 최적화 예외(딥 슬립 방지) 순차 요청
- 거부 시에도 앱 사용 가능하되, 배터리 예외 미설정 시 "화면 꺼짐 후 재생이 끊길 수 있음" 배너 고지 + 설정 화면에서 재안내

## 5. 범위 제외 (기획 확정)
- Shorts 전용 세로 스와이프 UI (Shorts 영상 자체는 일반 플레이어로 재생 가능)
- 댓글 작성·좋아요 서버 반영 등 로그인 필요 기능 (댓글 읽기는 2차 검토)
- 실시간 스트리밍(라이브) 지원은 1~2차 범위 제외, 3차에서 검토
