## 1. 프로젝트 개요

**UTub**은 화면 꺼짐/백그라운드 상태에서도 유튜브 콘텐츠를 광고 없이 재생·제어하는 **개인용 Android 앱**이다. 구글 로그인 없이 개인화(시청기록·대기열 등)를 전부 로컬 DB로 구현하며, APK 사이드로딩으로만 배포한다.

| 항목 | 내용 |
|---|---|
| 스택 | Kotlin 2.2 · Jetpack Compose(M3) · Media3 1.7.1(ExoPlayer/MediaSession) · NewPipeExtractor v0.26.5 · Room 2.7.2 · DataStore · Hilt 2.56.2 · OkHttp · Coil |
| SDK | compileSdk/targetSdk 36, minSdk 28 (갤럭시 S8+ 지원 위해 29→28 하향) |
| 구조 | 단일 `:app` 모듈 + 패키지 레이어링 (`extractor` / `playback` / `data` / `ui` / `webview` / `share`) |
| 빌드 | AGP 8.11.1, KSP 단일화(Room·Hilt), R8 + NewPipe/Rhino keep 규칙, 릴리스도 debug 키 서명(사이드로딩 전제) |
| 테스트 | JUnit5+MockK+Turbine(순수 로직) / JUnit4+Robolectric(Room·DataStore), 단위테스트 55개 통과 |

### 2.2 주요 방향 전환 이력

개발 이력에서 가장 중요한 사건은 **통합테스트 중의 두 차례 아키텍처 전환**이다.

1. **하이브리드 전환** (네이티브 → WebView): 사용자 피드백 "화면이 유튜브와 다르다" → 탐색/검색/채널 UI를 자체 네이티브에서 **m.youtube.com WebView**로 전환. 재생 엔진(Media3)·추출(NewPipe)·DB는 전량 재사용. 이로 인해 완성돼 있던 `HomeScreen`/`SearchScreen`은 NavHost에서 분리됨(현재 코드에 잔존).
2. **방식 A → 방식 B 재전환**: 방식 A(watch 페이지 위 네이티브 플레이어 오버레이 + 하단 웹 콘텐츠)에서 영상 중복·웹 잔존 문제 발생 → **방식 B(영상 클릭 가로채기 → 네이티브 상세화면 전환, 웹은 목록에 머무름)**로 최종 안정화.
3. **playNow 정책 변경** (2026-08-18): "현재 곡 뒤 삽입"이 대기열 무한 누적을 유발 → **"대기열을 새로 시작"**(유튜브 앱과 동일)으로 변경.
4. 기타: 테스트 기기 S8+(Android 9) → S20+(Android 13) 변경, 플레이어 컨트롤 컴팩트화, 홀로그램 유리 UT 로고 아이콘 적용.

### 2.3 통합테스트 중 결함 수정 이력 (docs/04 7-C)

### 2.4 통합테스트 현황 (docs/07)

- **자동(adb) 검증 통과**: 공유 즉시 재생, 타임스탬프 재생, 삭제 영상 예외 처리, 화면 끄기 직후 재생 유지, 대기열 복원(자동재생 안 함), 방식 B 전환, FATAL 크래시 0.

## 3. 아키텍처 개요

```
[유튜브 웹 (m.youtube.com)]                [네이티브]
 WebView + hybrid.js 주입                  MainActivity (NavHost: home/library/settings_tab/player/onboarding)
   ├ watch 클릭 가로채기 ──UTub 브릿지──▶ HybridWebViewModel → QueueManager.playNow
   ├ SPA 히스토리 훅                        │
   └ 광고/유튜브 크롬 숨김                    ▼
                                     PlayerStateHolder(@Singleton) ── queue: QueueManager (순수 로직)
                                          │ playSignal(세대 카운터)
                                          ▼
                                     PlaybackService (MediaSessionService, FGS)
                                          │ resolveAndPlay: 재생 직전 스트림 재추출
                                          ▼
                                     PlayerRepository → StreamExtractor(인터페이스)
                                          │                └ NewPipeStreamExtractor
                                          │                    ├ RateLimiter (250ms 간격 + 백오프)
                                          │                    ├ ExtractCache (TTL 10분)
                                          │                    └ OkHttpDownloader (429→RateLimited)
                                          └ Room(utub.db) / DataStore(utub_settings)
 UI 제어 경로: PlayerViewModel → PlayerConnection(MediaController) → 세션 커맨드
```

**핵심 설계 원칙** (코드에서 실제로 지켜짐이 확인된 것):
- **스트림 URL 비저장** — DB에는 videoId만 저장, 재생 직전 재추출. `DaosTest`가 리플렉션으로 URL 필드 부재를 구조적으로 강제.
- **NewPipe 격리 (N-03)** — `newpipe/` 패키지 밖에 `org.schabi.newpipe.*` import 0건. 유튜브 규격 변경 시 어댑터만 교체 가능.
- **이원 채널** — 재생 제어는 MediaSession(PlayerConnection), 대기열·모드·에러 상태는 PlayerStateHolder.
- **playSignal 세대 카운터** — StateFlow의 중복 제거(conflation)를 우회해 "같은 곡 재재생"을 표현.
- **순수 로직 분리** — QueueManager/BackgroundPolicy/SleepTimerManager/StreamSelector/ExtractCache/RateLimiter 6개가 Android 의존 0으로 전부 단위테스트됨.

## 4. 파일별 소스코드 분석

### 4.1 앱 진입점 / DI

#### `UTubApp.kt` (7줄)
`@HiltAndroidApp` 선언만 있는 Hilt 루트. ⚠️ `MainActivity.kt`의 private Composable `UTubApp`과 동일 패키지 내 이름 충돌(컴파일은 되나 혼동 유발).

#### `MainActivity.kt` (209줄)
유일한 액티비티이자 NavHost. `onCreate`에서 온보딩 여부를 `runBlocking`으로 동기 조회 후 시작 목적지 결정(onboarding > player > home). `PlayerViewModel`을 액티비티 스코프로 생성해 HybridScreen/PlayerScreen/MiniPlayerBar가 **동일 인스턴스 공유** — 미니↔전체 플레이어 상태 동기화의 근거. 하단 4탭(홈/Shorts는 같은 `home` 라우트 + `webTarget`/`webNavTick`으로 구분). `onStop`에서 `notifyAppBackground()`로 백그라운드 정책 트리거.
- 🔴 **`onNewIntent` 미구현**: `singleTask` + ShareReceiver의 `CLEAR_TOP` 조합에서, 앱 실행 중 공유 수신 시 재생은 시작되나 **플레이어 화면이 열리지 않음** (`EXTRA_OPEN_PLAYER` 무시됨).
- 🟡 메인 스레드 `runBlocking` 2곳(DataStore I/O) — 콜드 스타트 지연 위험. `settings` 라우트는 진입점 0건(죽은 라우트). 웹 내비게이션이 탭 선택 상태에 피드백되지 않아 desync 가능.

#### `di/AppModule.kt`
유일한 Hilt 모듈. `StreamExtractor`(→NewPipeStreamExtractor), `UTubDatabase`("utub.db"), DAO 3종, `SettingsRepository`를 제공. 별도로 `PlayerStateHolder`/`PlayerConnection`/`PlayerRepository`는 `@Inject constructor` 싱글턴.
- 🟡 Room **마이그레이션 전략 부재** + `exportSchema=false` → version 2 승격 시 즉시 크래시 위험. `QueueManager`는 DI 미경유(`PlayerStateHolder`의 필드로 직접 생성).

### 4.2 webview — 하이브리드 (방식 B)

#### `YouTubeUrlClassifier.kt`
URL을 `Watch(videoId, startMs)` / `Shorts`(웹 위임) / `WebNav` 3분기. **Shorts를 파서보다 먼저 체크**해 웹뷰 경로에서 쇼츠는 절대 네이티브 재생으로 넘어가지 않음. 단, 공유 인텐트 경로는 Classifier를 거치지 않아 쇼츠가 네이티브 재생됨(경로별 정책 차이 — 문서화 필요).

#### `YouTubeWebView.kt`
WebView Compose 래퍼. Chrome 128 모바일 UA 위장, `mediaPlaybackRequiresUserGesture=true`(웹 자동재생 차단 = 소리 겹침 1차 방어), `addJavascriptInterface("UTub")`로 `onWatchClicked`/`onNav` 수신(둘 다 `post{}`로 UI 스레드 마샬링). `shouldOverrideUrlLoading`에서 구글 로그인 차단 + Watch 인터셉트. `hybrid.js`를 `onPageStarted`/`onPageFinished` 이중 주입(JS측 가드로 멱등). `WebController`(람다 홀더)로 탭 버튼→웹뷰 조작.
- 🟡 `AndroidView`에 `update` 블록 없음(stale lambda 위험), WebView `destroy()` 미호출, JS 인터페이스가 모든 오리진에 노출되며 URL 검증 없음.

#### `assets/hybrid.js` (113줄)
주입 스크립트. ① 캡처 단계 click 핸들러로 watch 링크 선점(preventDefault) ② `pushState`/`replaceState` 몽키패치 + `popstate`로 SPA 감지 ③ 광고 셀렉터 5종 숨김 + MutationObserver ④ 유튜브 크롬(로고/헤더/하단탭) CSS 숨김 — 검색 페이지(`/results`)에서만 헤더 살림(`html.utub-search` 토글). watch 감지 시 `UTub.onWatchClicked` 호출 후 `history.back()`으로 웹은 목록에 유지(방식 B의 핵심).
- 🔴 **라인 40 `|| true` 디버그 잔재**: `if (Date.now() - lastGestureAt < 3000 || true)` — click 경로의 3초 제스처 게이트가 완전 무력화됨. 홈 피드 자동 미리보기 오인 방지 장치가 죽은 상태.
- 🟡 watch 인터셉트 경로가 3개(click 선점/히스토리 훅/shouldOverrideUrlLoading)인데 중복 제거·디바운스 없음 → 중복 재생 + `player` 백스택 중복 적재 가능. `[class*="topbar"]` 등 광범위 셀렉터는 유튜브 개편에 취약. 문서 전체 MutationObserver 2개의 성능 비용.

#### `HybridWebViewModel.kt`
watch URL → `queue.playNow(플레이스홀더 Item)` + `connect()` 변환하는 얇은 어댑터. 낙관적 UI(제목 "불러오는 중…" → 추출 후 실제 메타로 교체). 코루틴 미사용 동기 메서드라 사실상 유스케이스 클래스.

#### `HybridScreen.kt`
UTub 자체 헤더(로고+검색 버튼) + 웹뷰 조립. `BackHandler(enabled=webCanGoBack)`로 D3 수정 반영. `LaunchedEffect(webTarget, webNavTick)`로 탭 재클릭 대응.
- 🟡 `playerViewModel` 파라미터 미사용, `onNav={}` 빈 람다(탭 desync의 근본 원인), `navigate("player")`에 `launchSingleTop` 없음.

### 4.3 share — 공유 수신

#### `YouTubeUrlParser.kt`
Android 의존 0의 순수 파서. `Video(videoId, startMs, playlistId)` / `Playlist` / `LiveUnsupported` / `Invalid` sealed 결과. youtu.be/shorts/embed/watch/playlist/live 분기, 텍스트 내 URL 정규식 추출, `t=1h2m3s`·`t=90` 타임스탬프 파싱, 11자 videoId 검증. 모바일/뮤직 도메인 지원.
- 🟡 퍼센트 인코딩 미디코드, `#t=30` 프래그먼트 미처리.

#### `ShareReceiverActivity.kt`
투명 트램폴린 액티비티(`excludeFromRecents`, `taskAffinity=""`). ACTION_SEND/VIEW → 동일 파싱 경로 → Video면 `playNow` + MainActivity 기동(`EXTRA_OPEN_PLAYER`), Playlist/Live/Invalid는 안내 토스트 후 종료.
- 🔴 MainActivity `onNewIntent` 부재와 결합해 **앱 실행 중 공유 시 화면 미전환** (본 코드베이스에서 실사용 영향 최대 결함). 재생성 시 중복 재생 가능, `playlistId` 무시.

### 4.4 extractor — 스트림 추출

#### `Models.kt` (61줄)
도메인 계약: `VideoSummary`, `ResolvedStreams`(URL 영속화 금지 주석 명시), `VideoTrack`/`AudioTrack`, sealed `ExtractException`(Unavailable 7종 Reason/RateLimited/Network/Parse), `StreamExtractor` 인터페이스. NewPipe 타입 유출 0건 — 격리 원칙의 실체.

#### `newpipe/NewPipeStreamExtractor.kt` (180줄)
NewPipe 어댑터. `AtomicBoolean` CAS 지연 초기화 + 로케일/국가 설정(`setContentCountry` 변경 시 캐시 초기화), `resolveStreams` = 캐시 확인 → IO 디스패처에서 RateLimiter 경유 추출 → 라이브 차단 → 모델 변환(최대 해상도 썸네일, URL null 트랙 제거, related에서 StreamInfoItem만) → 캐시 저장. `mapErrors`의 catch 순서(구체→상위)가 NewPipe 예외 계층에 대해 올바름.
- 🟡 `ensureInit`이 초기화 완료 전 true 마킹(동시 진입 시 미완료 상태 추출 가능 — 이론적 경합), `trending`/`search`는 캐시 미적용, duration 0 영상은 완료 판정 불가. `extractVideoId`의 쿼리스트링 미제거는 입력이 NewPipe 내부 생성 URL뿐(`toSummary()` 한 곳 사용, 외부 URL은 `YouTubeUrlParser` 담당)이라 실질 위험 낮음.

#### `RateLimiter.kt` (43줄)
Mutex 기반 최소 250ms 간격 + `RateLimited` 시 지수 백오프(1s→2s), 3회 소진 시 전파. `nanoTime` 사용(벽시계 변경 무관), 시간/지연 함수 주입으로 가상시간 테스트.
- 🟡 KDoc "1s→2s→4s"는 오류 — `maxRetries=3` 기준 실제 대기는 1s·2s 두 번뿐(테스트는 실동작 기준으로 올바름). 락 안 delay로 동시 요청 직렬화(의도된 페이싱).

#### `ExtractCache.kt` (36줄)
TTL 10분(URL 만료 수 시간보다 짧은 안전 마진) + 최대 30개 인메모리 캐시. lazy expiration, `@Synchronized`, clock 주입.
- 🟡 LRU가 아닌 FIFO 축출(재-put 시 삽입 위치 미갱신), 능동 정리 없음.

#### `StreamSelector.kt` (43줄)
순수 선택 로직. 오디오 모드→최고 비트레이트, 비디오 모드→720p 이하 최고 muxed → video-only(+병합) → 최저 화질 → muxed 초과분 → 오디오 강등의 엘비스 폴백 체인.
- 🔴 `bestAudio` 계산이 최선행이라 **오디오 트랙 없이 muxed만 있는 영상은 재생 전면 실패**(muxed는 소리 포함이므로 논리상 재생 가능해야 함). 화질 설정 미배선(720 하드코딩 동작), 코덱 미고려.

#### `newpipe/OkHttpDownloader.kt` (52줄)
NewPipe `Downloader` 구현. 15s 타임아웃, removeHeader→addHeader 병합, **429 → `ReCaptchaException`** 변환(→RateLimited→백오프 연결), `use`로 바디 자동 close. `USER_AGENT`(Firefox 132)를 ExoPlayer `DefaultHttpDataSource`와 공유해 추출·스트리밍 UA 일치(봇 시그널 대응).
- 🟡 403/5xx는 Parse로 뭉뚱그려짐(503이 retryable=false), UA 하드코딩 노후화 위험.

### 4.5 playback — 재생 서비스

#### `PlaybackService.kt` (434줄) — 앱의 심장부
`MediaSessionService`. `playSignal` 관찰 → `resolveAndPlay`(이전 job 취소 → 재추출 → D2 메타 갱신 → 스트림 선택 → MediaSource 구성 3분기: 오디오 단일/Merging/muxed → prepare/play). 3단 예외 처리(ExtractException 한국어 매핑 → CancellationException 재throw → Throwable 방어). 알림 데코레이터로 일시정지 시 스와이프 삭제 허용(D4). 커스텀 커맨드 4종(STOP/AUDIO_ONLY/SLEEP_TIMER(0=취소,-1=영상끝,n=분)/APP_BACKGROUND). `switchAudioMode`는 현재 위치 캡처 후 재해석(위치 유지 전환). 15초 주기 영속화 + 정지 시 즉시 저장. `onTaskRemoved`: 재생 중 유지/정지 중 종료(음악 앱 관례).
- 🔴 **복원 후 재개 경로 단절 + 위치 유실**: `restoreQueue()`가 반환한 `positionMs`(`state.second`)를 사용하지 않을 뿐 아니라, 서비스 재시작 직후 ExoPlayer에 미디어 소스가 없어(`setMediaSource`는 `resolveAndPlay` 안에서만, 진입문은 `signalPlay()`뿐) `playPause()`로는 재생을 시작할 수 없음. 큐 항목 탭(`jumpTo`)만이 유일한 재개 경로이며 그때도 처음부터 재생됨.
- 🔴 **알림/블루투스 next·prev가 QueueManager에 연결 안 됨**: raw ExoPlayer를 세션에 넘기고 매번 단일 아이템 타임라인을 설치하는데 `ForwardingPlayer`가 없어, 잠금화면·블루투스의 스킵 명령이 대기열에 도달하지 못함(SCR-800 목표와 상충. 수동 통합테스트 IT-AUD-05에서 드러날 가능성 높음).
- 🟡 자동재생 시 `firstRelated`가 현재 영상을 재추출(TTL 10분 초과 영상은 종료 순간 풀 추출 — `stateHolder.related` 재사용 가능), `resolveJob` 취소 비동기성으로 `isResolving` 스피너 역전 가능.

#### `PlayerConnection.kt` (93줄)
UI↔서비스 Facade. `MediaController.buildAsync` + 리스너로 `isPlaying`/`isBuffering`/`durationMs` StateFlow 노출, 커스텀 커맨드 래퍼 4종.
- 🟡 `connect()` 재진입 가드가 비동기 콜백 구간을 못 덮음(컨트롤러 중복 생성 가능), 서비스 종료 후 stale controller 재연결 로직 부재.

#### `QueueManager.kt` (226줄) — 순수 대기열 로직
`playSignal` 세대 카운터(핵심 트릭), `playNow`=대기열 대체(정책 변경 반영), `playNext`/`addToQueue`/`move`/`removeAt`(현재 곡 삭제 시 다음 곡 자동 재생), 셔플(현재 곡 고정+원순서 복원+셔플 중 추가분 유지), `onItemEnded` 상태머신(ONE/ALL/OFF×자동재생, `relatedProvider` suspend 람다로 네트워크 분리), `updateMetaIfCurrent`(videoId 검증 race 방어, D2), `restore`(자동 재생 안 함).
- 🟡 data class 동등성을 아이덴티티로 사용 — 중복 항목 시 셔플/이동 오동작(Item에 UID 추가로 근본 해결 가능). 자동재생이 큐를 무한 append. `repeatMode`가 관찰 불가능한 public var.

#### `SleepTimerManager.kt` (84줄)

- 🔴 `state` StateFlow가 세션으로 전달되지 않아 **UI에서 잔여 시간 표시 불가**(사실상 dead code), 서비스 재기동 시 저장된 타이머 미복원.

#### `BackgroundPolicy.kt` (22줄)
3×2 진리표 순수 함수(ALWAYS/HEADSET_ONLY/OFF × 외부출력 여부). 패키지에서 가장 깔끔한 정책/부작용 분리. 트리거는 SCREEN_OFF 브로드캐스트 + APP_BACKGROUND 커맨드 2곳.

#### `PlayerStateHolder.kt` (52줄)
서비스↔UI 공유 상태 허브(`@Singleton`). `queue` 직접 소유 + `audioOnlyMode`/`error(PlaybackError)`/`isResolving`/`related` StateFlow 4종.
- 🟡 UI가 `queue` 가변 API에 직접 접근해 명령 채널이 이원화(세션 경유 vs 직접 접근), `related`/`error`의 초기화 시점 부재.

### 🔴 P0 — 기능이 실제로 동작하지 않거나 사용자가 바로 겪는 결함

| # | 위치 | 내용 |
|---|---|---|
| 1 | `MainActivity` + `ShareReceiverActivity` | `singleTask`+`CLEAR_TOP` 조합에 `onNewIntent` 미구현 → **앱 실행 중 공유 수신 시 플레이어 화면이 열리지 않음** |
| 2 | `hybrid.js:40` | `\|\| true` 디버그 잔재 → 클릭 경로 3초 제스처 게이트 완전 무력화 |
| 3 | `PlaybackService:396~` + `PlayerViewModel:79` | **대기열 복원 후 재개 경로 자체가 단절**. `restore()`는 의도적으로 재생을 트리거하지 않는데("사용자가 재생을 누르면 재추출"), 그 "재생을 누르면"에 해당하는 경로가 없다 — `playPause()`→raw ExoPlayer는 미디어 소스가 비어 있어 **앱 재시작 후 ▶를 눌러도 무반응**. 큐 항목을 직접 탭(`jumpTo`)해야만 재생되고, 그마저 복원된 `positionMs`(`state.second`)가 버려져 처음부터 재생됨 (TC-PB-18 의도 미달) |

## 6. 잘 된 설계 (유지할 것)

1. **NewPipe 격리(N-03)의 실질 이행** — 인터페이스 경계 밖 NewPipe 타입 유출 0건. 유튜브 규격 변경 리스크(R-01) 대응 구조가 문서 약속대로 코드에 존재.
2. **"URL 비저장 → 재생 직전 재추출" 원칙의 일관 적용** — 엔티티 설계·복원 로직·리플렉션 테스트까지 3중으로 강제.
3. **playSignal 세대 카운터** — StateFlow conflation을 우회해 "같은 곡 재재생"을 표현하는 간결한 트릭.
4. **순수 로직 6종 분리** — QueueManager/BackgroundPolicy/SleepTimerManager/StreamSelector/ExtractCache/RateLimiter가 Android 의존 0 + clock/random/람다 주입으로 결정론적 테스트 확보.
5. **예외의 대수적 표현** — sealed `ExtractException` → 서비스의 exhaustive 한국어 매핑, 429→ReCaptcha→RateLimited→백오프의 계층 연결.
6. **문서-코드 추적성** — D2(videoId race 검증), D4(알림 플래그 데코레이터), agy 검토 항목(미니플레이어 좌우 스와이프, 영구 거부 폴백)이 전부 코드에서 확인됨. TC-ID가 테스트 이름에 유지됨.
7. **UA 일치 전략** — 추출(OkHttp)과 스트리밍(ExoPlayer)의 User-Agent를 단일 상수로 공유해 봇 탐지 시그널 최소화.
