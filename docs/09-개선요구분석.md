## 0. 종합 진단 — 4건의 공통 뿌리

항목 2·3·4·5는 별개 결함이 아니라 **하나의 구조적 원인**에서 나온다: 탐색 UI를 유튜브 웹에 위임하면서 **유튜브 웹 DOM(CSS 클래스)에 의존**하게 됐고, 유튜브 웹 개편으로 `hybrid.js`의 셀렉터(`ytm-pivot-bar-renderer`, `ytm-mobile-topbar-renderer` 등 구세대 클래스)가 현재 DOM과 매칭되지 않는다. 이는 docs/08에서 P3로 예측했던 "유튜브 웹 개편 취약성"이 실제로 발현된 것이다.

**전략**: ① 웹 DOM 의존을 줄일 수 있는 것은 네이티브로 복귀(검색이 대표 — 이미 완성·테스트된 코드가 사장돼 있음), ② 불가피한 CSS 의존은 `hybrid.js` 한 파일에 국한시켜 앱 로직 무수정으로 갱신 가능하게 유지.

## 1. 내부 볼륨 기능 추가

> **✅ 구현 완료 + 실기기 검증 (2026-08-19)**: 아래 설계대로 구현 — `VolumeChip.kt` 신규, `PlaybackService`(userVolume + 곱셈 람다 + CMD_SET_VOLUME), `PlayerConnection`/`PlayerViewModel`(제곱 커브 변환 단일화), `SettingsRepository`(영속화 키). `SleepTimerManager`는 무수정. 단위테스트 64개 통과.
> 실기기 확인: ① 볼륨 칩·슬라이더 정상 동작(100→30%) ② **취침 타이머 설정→취소 후 볼륨이 낮은 값으로 유지 — 100% 점프 없음** (충돌 해소 확인) ③ **강제종료→재실행 시 저장 볼륨 정확히 복원**. 미확인 잔여: 타이머 만료 페이드의 실음 (단위테스트 커버, 사용자 청각 확인 권장).

### 현황 분석
- 앱 내 볼륨 UI 없음. 하드웨어 볼륨 키만 동작.
- ⚠️ **핵심 결함 리스크**: `SleepTimerManager`가 `player.volume`을 점유하고 있다 — 페이드아웃 시 0.9→0.0으로 낮추고, `cancel()`·만료 시 **무조건 `setVolume(1f)`로 복원**한다(`SleepTimerManager.kt:74~83`). 내부 볼륨을 `player.volume`으로 구현하면 취침 타이머를 취소하는 순간 사용자가 설정한 볼륨이 1.0으로 튀는 결함이 생긴다.

### 요구 확정 (2026-08-19 사용자 답변)
**기기 볼륨(휴대폰 미디어 볼륨)과 별개인 플레이어 전용 볼륨** — A안(`player.volume`) 확정.

### 충돌하면 실제로 어떻게 되는가 (사용자 질문에 대한 답)
`SleepTimerManager`는 페이드아웃을 위해 `player.volume`을 0.9→0.0으로 낮추고, **취소·만료 시 무조건 `setVolume(1f)`로 복원**한다. 플레이어 볼륨을 그냥 추가하면:
- 사용자가 플레이어 볼륨을 30%로 설정 → 취침 타이머를 걸었다가 **취소하는 순간 볼륨이 100%로 점프** (심야 이어폰 청취 시나리오에서 최악의 사용자 경험)
- 타이머 만료 후 **다음 재생이 100%로 시작** (설정한 30% 무시)
- 반대로 페이드 진행 중 사용자가 볼륨 슬라이더를 만지면 페이드와 슬라이더가 같은 값을 서로 덮어써 볼륨이 널뛴다

### 결함 없는 설계 (SleepTimerManager 무수정)
`SleepTimerManager`는 "볼륨 절대값"이 아니라 **"페이드 비율(0.0~1.0)"을 내보내는 것**으로 재해석하고, 실제 볼륨 적용부에서 사용자 볼륨을 곱한다:
- `PlaybackService`에 `userVolume` 상태(기본 1.0f) 추가, 타이머 생성 람다를 `setVolume = { player.volume = it * userVolume }`로 변경 (**기존 1줄 수정** — SleepTimerManager 자체는 손대지 않음)
- 페이드: 0.9×uv → 0×uv로 자연스럽게 사용자 볼륨 기준 페이드. 복원 `setVolume(1f)` → `1f×uv = uv` — **자동으로 사용자 볼륨 복원**
- 볼륨 변경 경로: 커스텀 세션 커맨드 `CMD_SET_VOLUME`(float) 추가 → 서비스가 `userVolume` 갱신 + `player.volume = uv` 적용. 기존 `CMD_SET_AUDIO_ONLY`와 동일 패턴이라 구조 이질감 없음
- 영속화(선택): DataStore에 저장하면 재시작 후에도 유지 — `SettingsRepository`에 키 1개 추가

### 구현 범위
- **신규 파일** `ui/player/VolumeChip.kt`: 볼륨 칩 + 드롭다운 슬라이더(0~100%)
- **기존 수정**: `PlaybackService`(람다 1줄 + 커맨드 분기 1개 + companion 상수), `PlayerConnection`(래퍼 함수 1개), `PlayerScreen`(칩 삽입 1줄)
- 검증 포인트: 볼륨 30% 설정 → 타이머 설정 → 취소 → **볼륨이 30% 유지되는지** / 페이드 만료 → 재재생 시 30% 유지되는지

## 2. 메인화면에 유튜브 헤더/푸터 노출됨

> **✅ 방침 확정·구현 완료 (2026-08-19, 사용자 승인: 숨김 최소화 + UTub 헤더 슬림화)**
> - **결함1 (콘텐츠 선택 후 복귀 시 로고/칩 미노출) 원인 확정**: ① 유튜브가 홈을 두 변형(피드형/빈 홈형 — Chrome 대조로 확인, 빈 홈형엔 칩이 원래 없음)으로 비결정 렌더 ② 우리 광범위 셀렉터(`[class*="search-box"]` 등)가 빈 홈형의 로고·검색창을 오폭해 "빈 화면"을 만듦. 뒤로가기는 방아쇠가 아니었음(뒤로가기 후 정상인 재현도 존재).
> - **수정**: `hybrid.js` 재작성 — 로고/상단바/검색창 숨김 전부 삭제(오폭 원천 제거), 광고 차단 유지, **유튜브 하단 탭만 숨김**(구세대 셀렉터 + 링크 기반 + 위치 기반 3중 탐지, "바 형태" 3중 가드로 오폭 차단 — 실패 시 탭이 보일 뿐인 안전한 실패 설계). `HybridScreen` 헤더 48→32dp 슬림화 + 검색 버튼 제거.
> - **디버깅 과정 기록**: 초기 구현이 실기기에서 동작하지 않아 debug 빌드에 WebView 디버깅(`FLAG_DEBUGGABLE` 가드)을 추가하고 DevTools 프로토콜로 원인 추적 — 하단 탭은 여전히 `ytm-pivot-bar-renderer`였으나, **onPageStarted 주입 시점에 `MutationObserver.observe(documentElement)`가 예외를 던져 초기화가 중단**(단계 마커로 사망 지점 확정)되고, 초입의 주입 가드 때문에 onPageFinished 재주입도 막혀 있었음. → observe 실패 시 재시도 + 옵저버와 무관한 2.5초 주기 스위프 보험으로 수정, 실기기에서 stage=done·sweep 동작·pivot display:none 확인.
> - **부수 효과**: `/results` 검색창을 죽이던 오폭이 사라져 **④(검색)가 추가 개발 없이 해결** — 유튜브 자체 검색창으로 검색 입력→결과("aespa" 검색 실기기 확인).

### 재현 결과 (확정)
콜드스타트 → 홈에 **유튜브 로고 헤더 + 카테고리 칩 + 유튜브 자체 하단 탭(홈/Shorts/내 페이지)**이 그대로 노출. UTub 헤더/탭과 이중 구조로 화면 낭비.

### 원인 (소스 대조)
`hybrid.js`의 `hideYtChrome()`(87~112행)이 숨기는 셀렉터는 구세대 DOM(`ytm-pivot-bar-renderer`, `ytm-mobile-topbar-renderer`, `c3-search-box` 등) 기준. 현재 m.youtube.com은 개편된 마크업이라 매칭 실패. 스타일 재부착 MutationObserver는 정상 동작하지만 **셀렉터 자체가 빗나가므로** 무의미.

### 개선 방향
1. **현재 DOM 클래스 확인이 선행 조건.** `YouTubeWebView.kt`의 WebView 설정에 debug 빌드 한정 1줄 추가:
   ```kotlin
   if (BuildConfig.DEBUG) WebView.setWebContentsDebuggingEnabled(true)
   ```
   → PC Chrome `chrome://inspect`로 실제 헤더/푸터의 클래스·태그 확인 (release 동작 무영향).
2. `hybrid.js`의 셀렉터 목록만 갱신 — **앱 코드(Kotlin) 무수정**. hybrid.js는 assets 자산이라 이 파일만 교체하면 됨.
3. **결함 예방 규칙**:
   - 광범위 부분일치 셀렉터(`[class*="search-box"]` 류) 추가 금지 — 이미 4번 항목(검색창 실종)의 유력 원인. 새 셀렉터는 확인된 정확한 클래스/태그로 한정.
   - 숨김 실패 감지 로깅: 주입 후 대상 매칭 수가 0이면 `console.log`(→ 필요 시 `UTub.onNav` 편승으로 앱에 전달) — 다음 개편 때 조기 발견.
4. **구조적 대안(장기)**: CSS 추격전은 반복될 운명이므로, 헤더/푸터 숨김이 또 깨져도 앱이 "이중 헤더" 정도로만 열화되고 기능은 유지되게 — 핵심 기능(재생 가로채기)은 URL 기반이라 DOM 개편과 무관하게 이미 견고함을 유지한다.

## 3. 우리 앱 헤더 > 로고(유튜브 아이콘) 탭 시 동작 안 함

> **✅ 구현 완료 + 실기기 검증 (2026-08-19)**: `HybridScreen`에 `onLogoClick` 추가(로고+이름 클릭 영역), `MainActivity`에서 홈 탭과 동일 경로로 연결. 실기기: Shorts 탭 상태에서 로고 탭 → **유튜브 홈 이동 + 하단 탭 하이라이트 '홈'으로 동기화** 확인.

### 원인 (소스 확정 — 결함이 아니라 미구현)
`HybridScreen.kt` 헤더의 로고 `Image`와 "UTub" `Text`에 **클릭 핸들러가 없다**. 하단 홈 탭만 `webTarget`/`webNavTick` 경로로 홈 이동을 트리거한다.

### 요구 확정 (사용자 답변)
UT 로고 탭 → **유튜브 홈으로 이동** (유튜브 앱의 로고 탭과 동일 동작 — 유튜브 앱은 로고 탭 시 홈 피드로 이동하고, 이미 홈이면 새로고침/맨 위 스크롤).

### 개선 방향
- 로고+타이틀 영역에 클릭 핸들러 추가. 단, `loadUrl` 직접 호출 대신 **하단 홈 탭과 동일 경로(`webTarget = YT_HOME` + `webNavTick++`)를 재사용** — 이렇게 해야 하단 탭 하이라이트도 함께 홈으로 동기화된다 (Shorts 탭에서 로고를 눌렀을 때 탭 표시가 어긋나는 desync 방지).
- 수정 범위: `HybridScreen`에 `onLogoClick` 콜백 파라미터 1개 + `MainActivity`에서 홈 탭 클릭과 같은 람다 연결 (~3줄). 이미 홈이면 같은 URL 재로드 = 새로고침 효과(유튜브 동작과 일치).

## 4. 우리 앱 헤더 > 검색 버튼 탭 시 검색 동작 안 됨

> **✅ 해결 (2026-08-19)**: ②의 숨김 최소화로 유튜브 자체 검색이 부활해 별도 개발 없이 해결. UTub 헤더의 검색 버튼은 제거(유튜브 헤더 돋보기가 대체). 실기기: 돋보기 탭 → 입력창+키보드 → "aespa" 검색 → 유튜브 원형 결과 페이지(아티스트·앨범·영상) 확인. 아래 A/B안 설계는 기록용으로 유지.

> **결함2 (쇼츠 진행바 터치 안 됨) 원인 확정 (2026-08-19)**: 탭/드래그 분리 실험 결과 — **탭 시킹은 유튜브 모바일웹 자체 미지원 사양**(진행바 70% 지점 탭 → 위치 불변), **드래그 시킹은 정상 동작**(정밀 드래그로 ~65%·~95% 지점 점프 확인, 2회). 유튜브 공식 앱 쇼츠도 동일하게 "바를 잡고 드래그"하는 방식. 미니플레이어 간섭은 ⑤에서 이미 제거됨. 조작법: 진행바를 꾹 잡고 좌우로 끌기.

### 재현 결과 (확정)
검색 버튼 탭 → `m.youtube.com/results`(빈 검색어)로 이동은 하지만 **검색 입력창이 화면에 없음** → 검색어를 입력할 방법 자체가 없음.

### 원인 (소스 대조)
`HybridScreen.kt`의 검색 버튼은 `controller.loadUrl("https://m.youtube.com/results")`만 호출 — **입력 UI를 유튜브 웹 헤더에 의존**하는 설계. 그런데:
- `hybrid.js`는 `/results`에서만 유튜브 헤더를 살리는 `utub-search` 모드를 두었으나, 개편된 DOM에서 예외 셀렉터가 빗나가거나,
- 광범위 숨김 셀렉터(`[class*="search-box"]`, `[class*="topbar"]`)가 새 DOM의 검색창까지 죽였거나,
- 빈 쿼리 `/results` 페이지가 애초에 입력창 없이 렌더링됨.
어느 쪽이든 **웹 DOM 의존이 원인**.

### 요구 확정 (사용자 답변)
"유튜브 검색 동작과 동일해야 함" — **검색어를 입력하면 유튜브 검색 결과가 나와야** 한다.

### 개선 방향 (권장: A안 — 네이티브 입력 + 유튜브 웹 결과)
유튜브와 동일한 화면·동작이 요구이므로, **입력 UI만 우리가 제공하고 결과 화면은 유튜브 웹을 그대로 쓰는** 구성이 요구에 가장 부합한다:

| 안 | 구성 | 유튜브 동일성 | DOM 의존 |
|---|---|---|---|
| **A. 네이티브 입력 + 웹 결과 (권장)** | 검색 버튼 → 우리 입력창 오버레이 → 제출 시 `m.youtube.com/results?search_query=<인코딩된 검색어>` 로드 | 🟢 결과 화면이 유튜브 그 자체 (필터 칩·연관검색·채널 결과 포함) | 입력에 한해 제거 — 결과 페이지 렌더는 유튜브가 알아서 |
| B. 풀 네이티브 SearchScreen 재연결 | 사장된 SearchScreen 라우트 연결 | 🟡 결과가 우리 UI(리스트) — 유튜브 화면과 다름 | 완전 제거 |

- A안 세부: **신규 파일** `webview/SearchOverlay.kt` — 헤더 자리에 나타나는 TextField(IME Search 액션) + 최근 검색어(기존 `SearchHistoryDao` 재사용 가능). 제출 시 `URLEncoder.encode(query, "UTF-8")`로 인코딩해 `controller.loadUrl(...)`. 자동완성까지 원하면 기존 `StreamExtractor.suggest()`(NewPipe) 재사용 — 웹 DOM과 무관.
- 결과 페이지에서 영상 탭 → 기존 watch 인터셉트로 네이티브 재생 (변경 불필요, 기존 흐름 그대로).
- **결함 리스크**: ① 검색어 미인코딩 시 한글/특수문자 깨짐 — 인코딩 필수 ② `/results` 페이지에서 유튜브 자체 헤더(뒤로가기·검색창)가 항목 ②의 숨김 셀렉터에 걸려 안 보일 수 있음 — 이번 재현에서 확인된 현상이므로, **셀렉터 갱신(항목 ②) 시 `/results` 페이지 처리를 함께 결정**해야 함 (유튜브 검색창을 살릴지, 우리 오버레이로 일원화하고 완전히 숨길지 — 후자가 UX 일관성상 깔끔).
- B안은 폐기하지 않고 폴백으로 유지 — A안도 유튜브 개편에 결과 페이지가 영향받을 수 있으므로, 완전 독립이 필요해지면 B로 전환.

## 5. 쇼츠 프로그레스바(탐색바) 이동이 안 됨

> **✅ 구현 완료 + 실기기 검증 (2026-08-19)**: ① 쇼츠 탭에서 미니플레이어 숨김(`MainActivity` 조건 1개) — 재생 중 항목이 있어도 쇼츠 탭에선 숨겨지고 홈 복귀 시 재표시됨을 확인. ② 미니플레이어 종료 임계값 150px→**72dp**(고밀도 오터치 종료 방지). 실기기: 숨김 상태에서 **진행바 수평 드래그 시킹 정상 동작**(~95% 지점 점프) 확인 — 가로채기 간섭 해소.

### 요구 확정 (사용자 답변)
세로 스크롤이 아니라 **쇼츠 하단 진행바를 드래그해 탐색(시킹)하는 동작**이 안 되는 것.

### 재현 결과 (원인 확정)
1. 쇼츠 재생 중 진행바는 **쇼츠 콘텐츠 최하단 가장자리**에 수 픽셀 두께로 표시됨.
2. **adb로 진행바 y좌표를 정확히 짚어 수평 드래그하면 시킹이 정상 동작** (같은 쇼츠의 후반부로 점프, 진행바 ~65% 이동 확인) — 웹 기능 자체는 살아 있다.
3. 문제는 **터치 타깃 겹침**: 진행바와 그 바로 아래 미니플레이어 상단 사이 간격이 원본 픽셀 ~56px(**약 3.6mm**)에 불과하다. 손가락 터치 중심이 조금만 아래로 내려가면 **`MiniPlayerBar`의 `detectHorizontalDragGestures`가 수평 드래그를 소비** → 시킹이 안 될 뿐 아니라, 드래그 누적이 150px을 넘으면 **`closePlayer()`가 호출돼 재생이 통째로 종료**되는 2차 피해까지 있다.

### 개선 방향
- **1단계 (권장)**: 쇼츠 탭에서 미니플레이어 숨김 — `MainActivity.kt` 노출 조건에 `webTarget != YT_SHORTS` 추가 (~1줄). 진행바 아래가 `NavigationBar`(수평 드래그를 소비하지 않음)가 되어 오터치 여지가 크게 줄어든다. 알림·잠금화면 컨트롤은 유지.
  - ⚠️ 리스크: `webTarget`은 탭 상태라 홈 탭에서 웹 내 쇼츠로 진입한 경우는 커버 못 함(기지 desync 이슈) — 1단계에선 수용, 완전 대응은 `onNav` URL 기반 판정(수정 범위 증가).
- **보강 (P2, MiniPlayerBar 자체 개선)**: 스와이프 종료 임계값이 px 고정(150)이라 고밀도 화면에서 너무 민감함 — dp 변환 + **세로 성분이 큰 드래그는 무시**(방향 의도 판정)하면 진행바 근접 오터치로 인한 "재생 종료" 2차 피해가 사라진다. `MiniPlayerBar.kt` 제스처 블록 ~5줄.
- 참고: 쇼츠 관련 나머지 제약(광고·백그라운드 미지원)은 원 기획 합의(docs/02 "쇼츠는 웹 위임") 그대로 유지.

## 6. 유튜브처럼 (영상이 계속 나오는) 미니플레이어는 불가능한가?

> **✅ 구현 완료 + 실기기 검증 (2026-08-20)**: 신규 `VideoMiniPlayerBar.kt` — 썸네일 자리에 `PlayerView`(56dp, useController=false)로 실제 영상 렌더. 기존 `MiniPlayerBar`는 보존, `MainActivity` 호출 1곳만 교체(1줄 롤백 가능).
> - **폴백 규칙**: 오디오 전용 모드·해석 중·서피스 준비 전(durationMs==0)에는 썸네일 표시 — 검은 사각형 노출 방지
> - **서피스 안전성**: `onRelease { player = null }`로 자기 서피스만 detach — 전체↔미니 전환에서 상대 뷰 서피스를 지우지 않음
> - 실기기: 미니에 실시간 영상 렌더(프레임 변화로 확정) / **미니→전체→미니 왕복 전환 모두 검은 화면 없이 영상 연속** / 재생 무단절 확인

### 답: 가능하다. 현 구조가 오히려 유리하다.

현재 미니플레이어는 썸네일+텍스트 바(64dp)이지만, 이 앱은 **액티비티 스코프로 공유되는 `PlayerViewModel.connection.player`(MediaController)**를 이미 갖고 있어, 이를 `PlayerView`에 붙이기만 하면 미니 카드에서도 영상이 렌더된다 — `PlayerScreen`이 이미 쓰는 것과 동일한 interop 패턴.

### 구현 방향 (기존 코드 보존)
- **신규 파일** `ui/player/VideoMiniPlayerBar.kt`: 기존 `MiniPlayerBar`를 복제·확장해 썸네일 자리에 `AndroidView { PlayerView }`(60dp 높이, `useController=false`) 배치. 오디오 전용 모드면 기존처럼 썸네일 폴백.
- **기존 수정 1곳**: `MainActivity.kt`의 `MiniPlayerBar(...)` 호출을 `VideoMiniPlayerBar(...)`로 교체 — **기존 `MiniPlayerBar.kt`는 남겨두어 즉시 롤백 가능**.
- 제약·리스크:
  - media3는 **하나의 서피스만 활성** — 전체 플레이어와 미니가 동시에 보이는 순간은 없으므로(라우트로 배타) 충돌 없음. 단 전환 시 `PlayerView.player` 재바인딩 순서(이전 뷰 해제 → 새 뷰 연결)를 지켜야 순간 블랙/프리즈가 없다. `PlayerScreen`의 `AndroidView.update` 패턴을 그대로 따르면 됨.
  - 화면꺼짐 오디오 유지 로직과의 간섭 없음 — 서피스는 UI 소관이고 서비스는 오디오를 계속 낸다(기존과 동일).
  - 웹뷰(홈) + 영상 동시 렌더의 성능 비용은 S20+급에서 문제없는 수준이나, 저사양 대비로 설정 토글(영상 미니플레이어 켬/끔)을 두면 안전.
- **유튜브식 "드래그 연속 축소" 제스처**(전체↔미니가 손가락을 따라 모핑)는 별도의 큰 UI 작업 — 1단계로 "미니 카드에 영상 렌더"만으로 체감 요구는 충족되며, 모핑은 3차 과제로 분리 권장.
- 참고: **시스템 PIP**(앱 밖 플로팅)는 별개 기능으로 3차 로드맵(F-40)에 이미 계획돼 있음.

## 7. 우리 앱 플레이어에서 전체화면은 불가능한가?

> **✅ 구현 완료 + 실기기 검증 (2026-08-20)**: 신규 `Fullscreen.kt`(회전·시스템바·컷아웃 유틸 + `findActivity`) + `PlayerScreen` 수정 — 영상 우하단 진입 버튼(유튜브 위치 관례), 전체화면 시 영상만 표시(동일 `AndroidView` 노드 유지로 서피스 무단절), 영상 탭으로 오버레이 컨트롤(시크바·재생·±10초·이전/다음·시간) 토글, `BackHandler`로 전체화면 해제가 화면 이탈보다 우선, `DisposableEffect`로 이탈 시 회전/시스템바 복원 보장.
> 실기기: 진입(가로+몰입+확장) / 오버레이 토글 / 뒤로가기 세로 복원 — **전 과정 재생 연속(1:32 이어짐, configChanges 덕에 액티비티 재생성 없음)** 확인. 전체화면 시크바는 초기 M3 기본 스타일이 두꺼워 포트레이트와 동일한 커스텀(3dp 트랙+10dp 썸)으로 교체 — 실기기 확인 완료 (2026-08-20).

### 합의 이력에 대한 답 (사용자 질문: "합의된 부분인가? 2차로 가는 건가?")
- **원래 1차 기획에는 포함돼 있었다**: docs/03 SCR-300 설계에 "가로 회전/전체화면 버튼 → 몰입 모드"가 명시됨.
- 그러나 **통합테스트 중 하이브리드 결함 수정 시점(docs/04 7-C)에 "가로 회전: 1차는 세로 고정(회전 미지원)으로 회피"로 조정** — 하이브리드 전환 리스크를 줄이기 위한 임시 회피였다.
- **2차로 명시 이관된 항목(화질 선택 칩·자막 CC — docs/06 범위 조정)과 달리, 전체화면은 2차 배정 문서가 없다.** 즉 "합의로 제외"된 게 아니라 "1차 안정화를 위해 보류"된 상태. 지금 구현해도 합의 위반이 아니며, 아래처럼 기술적 준비도 이미 절반 되어 있다.

### 답: 가능하다. 준비도 이미 절반 되어 있다.

현재 세로 고정(`screenOrientation="portrait"`)은 하이브리드 결함 수정 때 "1차는 회전 미지원으로 회피"한 의도적 결정(docs/04 7-C). 매니페스트에 `configChanges="orientation|screenSize|screenLayout|keyboardHidden"`이 **이미 선언돼 있어 가로 전환 시 액티비티가 재생성되지 않는다** — 전체화면 구현의 최대 난관(재생성으로 인한 재생 끊김)이 이미 해소된 상태.

### 구현 방향 (기존 코드 최소 수정)
- **신규 파일** `ui/player/FullscreenController.kt`: 전체화면 진입/해제 유틸 —
  1. 진입: `activity.requestedOrientation = SENSOR_LANDSCAPE` + `WindowInsetsControllerCompat.hide(systemBars())` + `systemBarsBehavior = BEHAVIOR_SHOW_TRANSIENT_BARS_BY_SWIPE`
  2. 해제: portrait 복원 + `show(systemBars())`
- **기존 수정 (PlayerScreen.kt, ~10줄)**: `isFullscreen` 상태 1개 + 컨트롤 행에 전체화면 버튼 1개 + `isFullscreen`일 때 비디오 영역을 `fillMaxSize()`로 확장하고 나머지(메타·대기열·연관영상) 숨김 + `BackHandler(enabled = isFullscreen)`으로 뒤로가기 시 전체화면 먼저 해제.
- 결함 리스크와 예방:
  - **서피스 연속성**: 동일 `PlayerView` 인스턴스를 유지(레이아웃 파라미터만 변경)해야 전환 순간 블랙이 없다 — `AndroidView`를 조건 분기 밖에 두고 Modifier만 상태에 따라 바꾸는 구조로.
  - **미니플레이어/탭바 노출**: 전체화면은 `player` 라우트 안이므로 미니플레이어는 원래 숨겨짐(기존 조건 재사용). 탭바도 동일. 추가 수정 불필요.
  - **펀치홀(cutout)**: 몰입 모드에서 `layoutInDisplayCutoutMode = SHORT_EDGES` 지정 권장.
  - **회전 복원 누락**: 화면을 나가는 모든 경로(접기·X·미니로 축소)에서 portrait 복원을 보장 — `DisposableEffect(onDispose)`에 복원을 걸어 누수 차단.

## 10. 후속 개선 (2026-08-20, 2차 세션)

### ⑤-2 쇼츠 자체 스크러버 (B안) — ✅ 구현·검증 완료

## 25. 결함 — "내 소리 유지" ON인데 내비 안내 시 여전히 덕킹 (2026-08-23, 사용자 실차 보고) ✅ 원인 실측·수정·검증 완료

## 22. 검색 결과 제목 표시 문제 — 재진단 (2026-08-28, 사용자 보고)
