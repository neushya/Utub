## 3. 아키텍처 / 프로젝트 구조

**단일 Gradle 모듈(:app) + 패키지 레이어링** (개인 프로젝트 빌드 단순화 — agy의 멀티모듈안 대신 채택. 교체 용이성은 인터페이스로 확보)

```
app/src/main/java/com/utub/
├─ extractor/                  # N-03 핵심: 추출 엔진 격리
│   ├─ StreamExtractor.kt      #   interface: resolveStream(videoId), search(q),
│   │                          #   suggest(q), trending(), channel(id), playlist(id)
│   ├─ newpipe/                #   NewPipeExtractor 구현체 + OkHttp Downloader
│   └─ RateLimiter.kt          #   요청 간 최소 간격 + 429 지수 백오프
├─ playback/                   # Media3 서비스 계층
│   ├─ PlaybackService.kt      #   MediaSessionService, FGS(mediaPlayback)
│   ├─ QueueManager.kt         #   대기열, 자동재생(연관 영상), 복원
│   ├─ NotificationProvider.kt #   MediaStyle + X(종료) 커맨드
│   └─ AudioModeController.kt  #   오디오/비디오 모드, 화면꺼짐 Surface detach
├─ data/
│   ├─ db/                     #   Room: Entity/DAO/Database
│   ├─ prefs/                  #   DataStore 설정
│   └─ repository/             #   Extractor+DB 조합 리포지토리
├─ ui/
│   ├─ home/ search/ player/ queue/ settings/ onboarding/
│   ├─ shared/                 #   VideoCard, MiniPlayer, 상태 컴포넌트
│   └─ theme/
└─ share/ShareReceiverActivity.kt  # ACTION_SEND + ACTION_VIEW(링크 탭) 수신
```

- UI(Compose) → ViewModel(StateFlow) → Repository → {StreamExtractor | Room | DataStore}
- PlaybackService는 Repository를 통해서만 추출 호출. UI와는 MediaController로 통신

| RecentPlay | videoId(PK), title, channel, thumbUrl, durationMs, lastPositionMs, playedAt, isCompleted | 간이 홈 "최근 재생" + 2차 시청기록/이어보기의 기반 |

**2차 추가**: Subscription(channelId PK, title, avatarUrl, addedAt), FeedItem(캐시), Playlist / PlaylistItem(N:M), WatchLater, Liked, Download(파일 경로·품질)

## 5. 핵심 로직 설계

1. **스트림 추출 파이프라인**: videoId → 메모리 캐시(TTL 10분) 확인 → NewPipe 파싱(IO 디스패처) → 비디오+오디오/오디오전용 스트림 선별 → MediaItem 구성 → ExoPlayer. 실패 시 1회 재시도 후 ErrorState.
2. **서비스 수명주기**: MediaSessionService + FOREGROUND_SERVICE_TYPE_MEDIA_PLAYBACK. onTaskRemoved: 재생 중이면 유지, 일시정지면 stopSelf. 알림 X 커맨드 → stop+release. Media3 setWakeMode(NETWORK)로 WakeLock 자동 관리.
3. **오디오/비디오 모드**: 화면 꺼짐(SCREEN_OFF) → Surface detach(오디오 지속), 켜짐 → reattach. 수동 오디오 모드 → 오디오 전용 트랙 선택(위치 동기 유지).
4. **백그라운드 재생 모드 설정 반영**: OFF면 SCREEN_OFF/onPause 시 pause. HEADSET이면 오디오 출력 장치 검사 후 결정. ALWAYS(기본)면 유지.
5. **오디오 포커스**: Media3 setAudioAttributes(handleAudioFocus=true) — 전화 시 일시정지·종료 후 재개, 덕킹 자동 처리. becomingNoisy(이어폰 분리) → pause.
6. **429/봇 확인 대응**: 전역 RateLimiter(요청 간 최소 250ms) + 429 시 지수 백오프(1s→2s→4s, 최대 3회) + 검색 디바운스 300ms.
7. **대기열 복원**: 종료 시 QueueItem + 현재 인덱스/위치 저장 → 재실행 시 목록 복원(스트림은 재생 직전 재추출).
8. **취침 타이머**: 만료 3초 전부터 볼륨 페이드아웃 → pause → 서비스 정리.

## 7-B. WebView 하이브리드 전환 설계 (2026-08-17, 통합테스트 중 결정)

배경: 사용자가 "유튜브와 동일한 화면"을 원함 → 탐색 UI를 WebView(유튜브 웹)로 전환. 재생 엔진·서비스·DB는 전량 재사용. (근거 memory [[utub-hybrid-pivot]])

### 구조
```
YouTubeWebActivity/Fragment
 └ WebView(m.youtube.com)  ← 탐색/검색/상세/연관영상/댓글/채널
     ├ JS 주입: 클릭 가로채기 + 웹 비디오 음소거/숨김 + 광고 최선차단
     └ JsBridge(@JavascriptInterface): onWatchClicked(videoId, startMs)
 └ (상세화면) 상단 오버레이 = 기존 네이티브 플레이어(SCR-300 재사용)
 └ 하단 탭: [유튜브](웹) [보관함](로컬) [설정]
 └ 재사용: PlaybackService, StreamExtractor, Room, 미니플레이어, 대기열, 알림/잠금화면
```

### WebView 설정
- javaScriptEnabled, domStorageEnabled = true
- mediaPlaybackRequiresUserGesture = true (웹 자동재생 차단 — 소리 겹침 1차 방어)
- UA = Chrome 모바일 표준 (구글 로그인 disallowed_useragent 회피)

### watch URL 클릭 인터셉트 (3중 방어, SPA 대응)
1. **문서 클릭 캡처링**(document.addEventListener('click', …, true)) — 최우선. 웹 재생 시작 전 a[href*="/watch"] 선점, preventDefault
2. **history.pushState/replaceState 후킹** — SPA 라우팅 감지(폴백)
3. **shouldOverrideUrlLoading** — 초기/외부 링크 보조
→ JsBridge로 videoId 전달 → 우리 플레이어 재생

### 분기 로직
- `/watch?v=`, `youtu.be/` → 가로채서 네이티브 재생
- `/shorts/` → 웹에 위임(가로채지 않음)
- 그 외(홈/검색/채널/재생목록) → 웹 탐색 유지

### 방식 A 오버레이 + 웹 비디오 차단
- CSS 주입: 웹 player 컨테이너 visibility:hidden/height:0
- MutationObserver: 새로 생기는 <video>에 muted=true; pause()
- 상단 네이티브 플레이어 오버레이 + 하단 웹 콘텐츠 스크롤
- 연관영상(웹) 탭 → 인터셉트 → 오버레이 플레이어 새 영상으로 교체

### 재사용 / 폐기
- 재사용: PlaybackService, StreamExtractor/NewPipe, RateLimiter, Room DB, 미니플레이어(SCR-310), 대기열(SCR-320), 알림/잠금화면(SCR-800), 보관함(SCR-500), 설정(SCR-700)
- 폐기/대체: 자체 홈 피드(SCR-010/100), 검색 UI(SCR-200), 채널 UI(SCR-600) → 웹뷰. SCR-300은 연관영상/댓글 섹션 제거하고 오버레이 플레이어로 축소

### 신규 테스트
- 단위: TC-WV-01(URL 분류 watch/shorts/기타), TC-WV-02(JsBridge videoId 추출·디스패치)
- 통합: IT-WV-01(웹 피드 탭→네이티브 재생), IT-WV-02(쇼츠 웹 위임), IT-WV-03(소리 겹침 0), IT-WV-04(뒤로가기 오버레이/웹 히스토리)

### 리스크
- 유튜브 웹 변경 → 인터셉트/음소거 깨짐: 3중 방어로 완화, 그래도 유지보수 필요
- 목록 광고 잔존: CSS/JS 최선차단, 완전 차단 보장 안 함(사용자 고지 완료)
- 로그인 차단: 표준 UA + 비로그인 로컬 보관함 정책 유지

## 7-C. 하이브리드 결함 수정 (2026-08-17, 실기기 통합테스트 중)

실기기 검증에서 발견된 결함 4건 + agy 교차검토로 도출한 잠재결함 예방을 함께 수정.

### 수정 대상 결함
- **D1 방식A 미작동**: hybrid.js가 preventDefault로 웹 이동을 막아 하단 웹이 홈에 머묾 → 상세정보 안 보임
  - 수정: **접근 변경** — watch 링크 클릭 시 preventDefault를 **제거**하고 웹은 자연스럽게 상세페이지로 SPA 이동하게 둔다. 소리 겹침은 웹 비디오 차단(음소거+CSS 숨김+MutationObserver)으로만 막는다. 네이티브 재생은 onNav(watch URL 감지)에서 트리거. → loadUrl 재로딩 없음(깜빡임/소리튐 회피, agy ①③ 반영)
- **D2 오버레이 제목 '불러오는 중' 고정**: 추출완료 후 QueueManager.Item 미갱신
  - 수정: PlaybackService가 추출 완료 시 `queue.updateCurrentMeta(videoId, title, channel, thumb, duration)` 호출. **videoId 일치 검증**(race 방지, agy 반영). Room 최근재생도 실제 메타로 기록
- **D3 뒤로가기 앱종료**: BackHandler.enabled가 웹뷰 canGoBack 변화 미반영
  - 수정: canGoBack을 mutableStateOf로, WebViewClient.doUpdateVisitedHistory + JS pushState 후킹(onNav)에서 갱신. 순서: 오버레이>웹히스토리>기본. 오버레이 닫을 때 웹은 유지(2회 뒤로가기 방지 위해 오버레이=상세와 동기화 검토)
- **D4 알림 X버튼/삭제 불가**: 알림 커스터마이징 전무
  - 수정: MediaSession 커스텀 layout에 stop CommandButton 추가, 종료 시 stop+release+stopSelf. 일시정지 시 `stopForeground(STOP_FOREGROUND_DETACH)`로 스와이프 삭제 허용(agy 반영)

### 잠재결함 예방 (agy 지적)
- 소리 중복: mediaPlaybackRequiresUserGesture=true + 웹 video display:none 사전주입
- 연관영상 재진입: player 재생성 아닌 트랙 교체(setMediaItem류) — 우리 구조는 resolveAndPlay 재호출로 세션 유지
- 상/하단 메타 중복: 오버레이는 영상+최소 컨트롤만, 제목/채널/댓글은 웹에 위임(오버레이 텍스트 최소화)
- 구글 로그인 진입: accounts.google.com 감지 시 안내 토스트 후 차단
- 가로 회전: 1차는 세로 고정(회전 미지원)으로 회피
- 웹뷰 메모리: 페이지 전환 시 숨긴 video 요소 제거

## 8. 2·3차 단계 계획 (개요)

- 2차: 홈 피드·채널·구독 탭(FeedItem 캐시+주기 갱신), 보관함(기록/나중에/좋아요/재생목록), 다운로드(Media3 DownloadService), Takeout 임포트(CSV 파싱+배치)
- 3차: PIP, SponsorBlock(공개 API), 구간 북마크, 백업/복원(JSON), 채널별 배속
- 상세 WBS는 각 단계 착수 시 본 문서에 추가
